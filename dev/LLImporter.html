LLImporter

Imports the data of an external workbook into the linelist that holds this object. CheckImportFile reads the file and says whether it can be imported, HasSameLanguage compares the two interface languages, and CurrentLanguage answers the language of this linelist. ImportData brings the HList and VList data in, ImportCustomDropdown the custom dropdowns, ImportShowHide the show/hide choices, ImportEditableLabels the labels a user may edit, ImportSingleValues the single metadata values and ImportGeobase the geobase. ClearData empties the linelist first when the caller asks for it, and HasData says whether the linelist already carries rows.

THE REPORT

CompareWithImportFile records which sheets and which variables the two files have in common and which they have on their own. NeedReport says whether anything was recorded, FinalizeReport writes the entries into ImportReport, ReportSheets and ReportVariables read them back, and ClearReport empties them. Entries filed along the way leave through HasCheckings and CheckingValues.

Depends on: LLdictionary, Passwords, CustomTable, DataSheet, LLGeo, LLChoices, LLVariables, DropdownLists, HiddenNames, ShowHide, ShowHideLayout, ShowHideStore, ChoiceKeys, ImportMetadata, Checking, BetterArray, ImportReport

ClearData #

clear-data

Clear all user-entered data from HList and VList sheets

Signature:

Public Sub ClearData()

Walks every worksheet of the source workbook. An HList sheet has the constant cells of its table body cleared and its formula columns left standing; a VList sheet has the constant cells of its value column cleared the same way. Each sheet is unprotected and protected again through Passwords.

WHAT IT COST BEFORE

An HList paid three crossings per column: one to resolve ListColumns(n).DataBodyRange, one to read HasFormula off its first cell and one to ClearContents. A VList paid three per ROW: the IsEmpty test on the label, an Offset onto the value cell and a HasFormula read on it, one row at a time down column D. A wide table and a long VList sheet both paid for every one of them.

Now each sheet reads its formulas as one block and clears the runs of cells between them. A table of 200 columns with no formula in it goes from about 600 crossings to two.

ONE CALCULATION, AT THE END

There was a lo.Range.Calculate per table and a sh.UsedRange.Calculate per VList sheet, so a workbook of ten data sheets recalculated ten times while it was being emptied. The clear is one walk and it recalculates once, after the last cell is cleared. RecalculateSheets is the same pass the import walk uses.

Walks the dropdown registry of the source workbook, reads the values the import workbook holds for each dropdown, and writes them back. Silently exits when the import workbook has no Choices sheet or the custom dropdown sheet does not exist.

ImportShowHide #

import-show-hide

Import show/hide choices from a migration workbook

Signature:

Public Sub ImportShowHide(ByVal impwb As Workbook, ByVal meta As ImportMetadata)

Reads the show/hide table of the import workbook and puts each data sheet of the running workbook in the state it describes: visibility, sizes and, on a printed sheet, the direction of each header. Every layer a sheet has is covered - HList and CRF for a data entry sheet, Printed for its companion, VList for an info sheet.

Two faults used to sit here. The visibility read out of the file was written into memory and never reached a sheet, so nothing was ever hidden; and a blank width cell was read as a width of zero and written to the sheet, which is how Excel hides a column, so entries vanished for the opposite reason.

Skips when The imported file has no show/hide sheet, and when its show_hide tag asks for no update.

Parameters:

  • impwb: Workbook. The opened migration workbook.
  • meta: ImportMetadata. The metadata of that workbook.

ImportEditableLabels #

import-editable-labels

Import editable label values from a migration workbook

Signature:

Public Sub ImportEditableLabels(ByVal impwb As Workbook, ByVal meta As ImportMetadata)

Reads the import workbook dictionary for editable label values and updates both the worksheet cells and dictionary entries in the source workbook. Skips when The imported file has no Dictionary sheet, when that dictionary is not prepared, and when the editable_labels tag asks for no update.

ONE HIDDEN NAMES STORE PER SHEET

The walk reads one name, table_name, off the sheet a variable lives on. HiddenNames.Create walks every tracked name of that sheet and reads three properties off each, and a data entry sheet holds hundreds of names. Built inside the loop, a dictionary of 500 variables paid 500 of those walks for a handful of sheets. The stores are held in a Collection keyed by sheet name, so each sheet is walked once however many of its variables carry an editable label. QuickValue is not the answer here the way it is in SheetTagOf: this walk asks the same sheet again and again, which is the case the instance is for.

THE DICTIONARY COLUMNS ARE READ AS BLOCKS

The walk used to make four LLVariables.Value calls per variable, plus one cell read of the name column, and each of those calls costs two crossings. Both dictionaries are read as blocks now, once, and every question below is answered from memory. LLVariables stays for the WRITE alone. The current dictionary answers at the row the walk is standing on rather than through a name lookup. For a name that appears twice, LLVariables.Value would answer with the first row of the pair both times round; reading the row in hand is what the loop meant. LLdictionary.UniqueVarNames makes the names unique during preparation, so neither shape has anything to do in practice.

Parameters:

  • impwb: Workbook. The opened migration workbook.
  • meta: ImportMetadata. The metadata of that workbook.

ImportSingleValues #

import-single-values

Import single metadata values from a migration workbook

Signature:

Public Sub ImportSingleValues(ByVal meta As ImportMetadata)

Takes the epiweek start value The imported file has and writes it into the RNG_EpiWeekStart hidden name of the source workbook, then recalculates every sheet that carries an epiweek formula. Skips when the file names no value.

THE NAME HAS NO RANGE BEHIND IT

RNG_EpiWeekStart is a HiddenNames entry and HiddenNames writes a string as a quoted literal in the name definition. So the name exists, Names(...) finds it, and asking that name for a range raises 1004. The write used to go through Names(RNG_EpiWeekStart).RefersToRange.Value under a swallow, which means the value has never once landed. The store is what answers it, the same way FormLogicEpiWeek and CustomLinelistFunctions already read and write it.

Parameters:

  • meta: ImportMetadata. The metadata of the workbook being imported.

RecalculateSheets #

recalculate-sheets

Recompute every data and analysis sheet, once

Signature:

Public Sub RecalculateSheets()

THE ONE CALCULATION OF A WALK. ClearData calls it when it has emptied the last sheet, and LinelistRun.HandleImportData calls it after its last write and before the busy state goes back. It used to run per sheet inside ImportData, per table and per VList sheet inside ClearData, and once more from ImportSingleValues, so one import recalculated the workbook many times over.

WHY THE LIST OF TAGS IS WHAT IT IS

Every epiweek formula reads RNG_EpiWeekStart, and the date and validation functions of CustomLinelistFunctions carry no Application.Volatile call on purpose -- the note at the head of that module says so, and says that this pass is what brings Excel back to them. So the tags here have to keep covering every sheet that can hold one of those formulas. FormLogicEpiWeek runs the same list after the user picks a day.

Delegates to LLGeo.Import to load geobase data. When not histoOnly, also updates geobase headers in HList worksheets via geo.Update and dictionary geo labels via geo.UpdateDict.

THE SHOW/HIDE SHEET IS NOT TOUCHED

CompareWithImportFile #

compare-with-import-file

Compare the labels and the choice lists of the two files

Signature:

Public Sub CompareWithImportFile(ByVal impwb As Workbook)

Walks the dictionary of this linelist and, for every variable the file also carries, files a warning when the two disagree about the label or about the values a choice variable may take.

WHY THE CHOICE LISTS MATTER MORE THAN THE LABELS

A data validation dropdown does not block a programmatic write. CustomTable writes the imported column straight into the cells, so a value the receiving linelist does not offer lands in the cell and stays there: the cell shows something no dropdown can produce, the next hand edit of it is rejected, and every analysis grouping by that variable gains a category the setup never declared. None of that used to appear anywhere.

Run this after ImportData, so the sheets that were touched are known.

Parameters:

  • impwb: Workbook. The opened import workbook.

ClearConstantsAcross #

clear-constants-across

Clear the constant columns of a table body, formula columns kept

Signature:

Private Sub ClearConstantsAcross(ByVal bodyRng As Range)

The first body row is read as one block, and a column whose first cell holds a formula is kept. That is the reading the per-column HasFormula read made too: a table column holds one formula all the way down or none at all.

A column that LOOKS like a formula is confirmed with one HasFormula read before it is kept. Range.Formula answers the text of a cell that holds "=abc" behind a leading apostrophe as well, and a false reading there would leave a column of typed data standing after the user asked for it to be deleted. Formula columns are the few, so the confirmation costs a crossing for each of them and nothing for the rest.

Parameters:

  • bodyRng: Range. The data body of the table.

ClearVListValues #

clear-vlist-values

Clear the value column of a VList sheet, formula cells kept

Signature:

Private Sub ClearVListValues(ByVal sh As Worksheet)

The labels of column D are read as one block and walked to the first empty one, which is where the cell-at-a-time loop stopped as well. Reading to the end of the used range instead would empty cells below a gap that the loop never reached, so the block is walked the same way rather than to its end.

The value column is then cleared in runs, the formula cells left standing. The audit asked for the column to be cleared in one call; it cannot be. A VList value cell holds a formula whenever its variable carries a formula, case_when or choice_formula control, and one call over the column would delete every one of them.

Parameters:

  • sh: Worksheet. The VList data entry sheet.

ReadDictBlocks #

read-dict-blocks

Read the columns the two comparison walks need, one crossing each

Signature:

Private Sub ReadDictBlocks(ByVal dict As LLdictionary, ByRef blocks As TDictBlocks)

Every LLVariables.Value call pays TWO crossings: ResolveColumnIndex checks the header cell still reads as the column it cached, then the value cell is read. ImportEditableLabels made four of those per variable plus a cell read of the name column, and CompareWithImportFile made several per variable on BOTH files, so a dictionary of 500 variables paid thousands of crossings for eight columns. Eight crossings per dictionary now, and the walks answer from memory. A column the dictionary does not carry answers a block of empty strings, so a caller reads it like any other and an older file costs no special case.

Parameters:

  • dict: LLdictionary. The dictionary to read.
  • blocks: TDictBlocks. Filled with one array per column.

ValuesMissingFrom #

Values are matched exactly. ImportVListSheet #

import-vlist-sheet

Import VList data from a single import sheet to the current sheet

Signature:

Private Sub ImportVListSheet(ByVal currsh As Worksheet, ByVal impsh As Worksheet)

Walks the rows of the import sheet, resolves each variable name to a named range on the current sheet and copies the value across when the target cell holds no formula. A name the sheet has no range for is filed as "not imported".

THE FILE IS READ IN ONE BLOCK

It used to read usedRng.Cells(counter, 1).Value and usedRng.Cells(counter, 2) .Value off the worksheet a row at a time, so a VList of 300 variables paid 600 crossings to read a file it could have read in one. The block is read once and the walk answers from the array; the writes stay one per variable, because each one lands on a named cell of its own somewhere on the sheet.

The block is indexed the way usedRng.Cells was, relative to the top left of the used range rather than to A1, so a file whose used range does not start at A1 is read exactly where it was read before.

A file of one row carries its header and nothing else, and a file of one column carries names with no value column beside them. Range.Value answers a scalar for the first and the walk never starts; the second used to read the cell to the right of the used range, which is empty, so an absent value column reads as an empty value here too.

Parameters:

  • currsh: Worksheet. The current source VList worksheet.
  • impsh: Worksheet. The import VList worksheet.
