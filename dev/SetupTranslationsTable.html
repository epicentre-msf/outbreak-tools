SetupTranslationsTable

Manages a translations ListObject backed by a helper tag column. Synchronises translations from a watcher registry, handles language column creation and promotion, removes obsolete and duplicate labels, reports missing and duplicate entries, and exports the table to external workbooks. Uses HiddenNames for sequence counters.

LABEL MATCHING POLICY

A label is always matched without regard to case. FindLabelRow, DeduplicateLabels and ComputeDuplicateSummary all answer from one keyed Collection whose key is the lower-cased label, so "Hello" and "hello" are one label everywhere. Mac Excel has no Scripting.Dictionary, so a keyed Collection is the house lookup. The only comparison that stays case-sensitive is the TagInternal header title, which is a fixed internal marker.

THE HELPER TAG COLUMN

The translations ListObject sits with one spare worksheet column to its left holding a tag per row, shaped __. That column lives outside the ListObject most of the time. During an update the table is resized one column left so each tag travels with its row through the sort, then resized back. LabelColumnIndex() answers 2 while the tag column is inside the table and 1 otherwise, and every column index in this class comes from that one function.

CREATE WRITES NOTHING

Create locates and validates the helper column. The title, the formatting and the hidden language list are written by the update path alone (EnsureTagColumnReady and EnsureLanguages), so a caller that only reads can build a manager over a protected sheet.

SOURCE RANGES ARE CONTIGUOUS

A registry range refers to one block of cells on one worksheet. SetupPreparation and UpdatedValues both build their names over a single table column, so that always holds. ProcessTextRange and ProcessFormulaRange read each source in one crossing, and Range.Value2 answers for the first area of a range, so a name built by hand over scattered cells would import its first block and drop the rest.

ERROR NUMBERS

ProjectError.ErrorUnexpectedState is 1004, which is also Excel's generic error number. An Excel 1004 that escapes an update is re-raised as 1004, so a caller reading the number alone cannot tell the two apart. Nothing acts on that distinction today.
