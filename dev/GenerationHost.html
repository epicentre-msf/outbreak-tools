GenerationHost

Carries the whole platform difference of a linelist build in one object. A build runs as the steps of BuildSteps, and this class owns the Excel instance those steps run in. On the instance path (Windows, the chkBuildInPlace box unchecked) Acquire starts a hidden Excel, OpenDesignerCopy writes a copy of the designer and opens it there, Run reaches a step through Application.Run across the two processes, and ReleaseInstance closes the copy and quits the instance this object started. On the in-place path (Mac always, Windows when the box is checked) the instance is the designer's own, the copy is the designer itself, Run is an in-process Application.Run and ReleaseInstance is a no-op.

GenerationHost.cls without interface: single implementation, no test fake, no compile cycle.

THE HIDDEN INSTANCE SHOWS NOTHING

The instance is started with Visible False, DisplayAlerts False, EnableEvents False, AskToUpdateLinks False and AutomationSecurity Low. Low is the level the steps need: ForceDisable turns off every macro of the opened copy and Application.Run answers 1004. The events stay off through EnableEvents False, so the copy's Workbook_Open and ribbon load stay quiet. Calculation is set to manual once the copy is open, because the write raises 1004 on an instance holding no workbook.

SCREENUPDATING IS OFF IN THE HIDDEN INSTANCE

An invisible Excel still repaints when ScreenUpdating is on, and Excel 16.0.20430 keeps shared graphics memory on every one of those repaints: about 0.7 MB per cell write, measured on 2026-10-01. On a laptop that memory is system RAM. The Info sheet of the ebola setup, 7 variables, cost 168 MB and ran six times slower, and the Linelist sheet of 511 variables took 219 seconds against 93 with ScreenUpdating off. So Acquire switches ScreenUpdating off there and Run writes it off again before every step.

THE OUTPUT WORKBOOK IS PAINTED ONCE, FROM THIS SIDE

A window that was never painted refuses Window.FreezePanes with 1004, and with ScreenUpdating off for the whole build the window of the output workbook is never painted: every data entry sheet came out unfrozen. Nothing a macro of the instance does paints it. Switching ScreenUpdating on inside the step, with the sheet activated, the zoom written, a scroll, a cell rewritten, Application.Wait or DoEvents after it, was refused every time (tried 2026-10-01). What paints it is ScreenUpdating switched on from THIS side while the instance sits idle between two steps, and off again right after. PaintInstance does that. The driver calls it once the output workbook exists, after the linelist step, and every freeze of the build is accepted from then on: Info and the 511 variable Linelist sheet of the ebola setup both froze, the shared graphics memory of the instance stayed at 18 MB, and the sheet took the same time with and without it.

A CALL THIS EXCEL STOPPED WAITING FOR

A step that runs long makes the visible Excel raise its box "waiting for another application to complete an OLE action", and the pending call can end cancelled: Run then sees -2147418110 while the step carries on in the instance and finishes. Its answer is still there. BuildSteps keeps what its last step answered, and after a dropped call Run asks for it through LastAnswer, waiting for the instance to come free. The step named by LastAnswerStep is the one asked; RecoveredCalls counts the answers read back that way, for the driver to file in its report.

THE COPY OPENS READ-WRITE

The copy is a private temp file named __designer_copy.xlsb that is never saved, so it opens read-write. A read-only open of the same file costs 9 to 20 seconds against 0.6; that difference is what makes the hidden build run at the in-place speed. A user file never carries the copy's name.

A RAISE INSIDE A STEP IS A HANG

Application.Run opens a fresh call stack, so an untrapped raise inside a step reaches no handler here, on either path. In place it shows the runtime error box; across the processes the hidden instance shows the VBE box, un-hides itself, and the visible side blocks. Every step therefore keeps its own handler and answers a string, and Run passes that string through. A raise Run sees on the visible side is one of three things. The instance gone (462, RPC call failed, RPC server unavailable) is answered as "the build instance stopped answering after " with the instance marked stopped so ReleaseInstance quits nothing. A call dropped on this side while the instance was at work is answered with what the step answered, read back from the copy. A plain fault, such as a step name the copy does not carry, is answered as "ERROR (): ".

RELEASE RUNS FROM EVERY EXIT

ReleaseInstance closes the copy without saving, quits the instance this object owns and deletes the copy file. It runs from Class_Terminate too, under On Error Resume Next, so a driver that raises on its way out still frees the instance. A Quit that fails leaves the instance and answers its window handle, taken at Acquire, for the driver to log. The instance is never found by process name.

CheckOpenNames #

check-open-names

Apply the file-name rules to the files a build opens

Signature:

Public Function CheckOpenNames(ByVal paths As BetterArray, _
                               Optional ByVal target As Application = Nothing) As String

Excel refuses to open a file whose name matches one already open in the same instance, and to save onto a file open anywhere. Two rules: two files of the list sharing a name is a refusal naming both paths, and a name already open in the target instance is a refusal naming the open file. Names compare without regard to case; empty entries are skipped. The target is the instance the build runs in once Acquire ran, or the designer's own before, so on Mac the designer itself is one more open name and on Windows the copy is. A driver checks the visible side by passing its own Application.

Parameters:

  • paths: BetterArray. Full paths, or bare file names. Nothing checks nothing.
  • target: Optional Application. The instance to check against. Nothing takes the host's.

Returns: String. Empty when nothing clashes; otherwise one refusal per line, vbLf between them.

The steps

Run #

run

Run one build step inside the workbook the steps run in

Signature:

Public Function Run(ByVal stepName As String, ParamArray arguments() As Variant) As String

Application.Run over the step name, qualified with the workbook the steps run inside: the copy in the instance, the designer in place. The name may carry its module, as in "BuildSteps.BuildSheet". Up to three arguments are forwarded; across the processes they have to be strings or numbers, since a workbook object cannot cross. The step's answer comes back as text. A raise on the visible side comes back as an outcome string too: the instance gone is "the build instance stopped answering after " and marks the instance stopped; any other fault is the plain error outcome. Once the instance is marked stopped every later Run answers the stopped outcome without a call.

A call this Excel stopped waiting for (cancelled, rejected, or told to come back later) is answered from the copy: the step carries on over there, so Run waits for the instance to come free and reads back what the step answered, through LastAnswer. The driver then sees the answer of the step itself. On the instance path ScreenUpdating is written off before the step, whatever the step before it left.

Parameters:

  • stepName: String. The public function to run.
  • arguments: ParamArray. Up to three arguments for the step.

Returns: String. What the step answered, or an "ERROR ..." outcome.

Throws:

  • ProjectError.ErrorUnexpectedState When OpenDesignerCopy has not run.
  • ProjectError.InvalidArgument When more than three arguments are handed over.

PaintInstance #

paint-instance

Let the hidden instance paint its windows once

Signature:

Public Function PaintInstance() As String

ScreenUpdating on, then off, as two calls from this side with the instance idle between them. That one paint is what makes the window of the output workbook take its freezes for the rest of the build; see the note at the top of this class. In place nothing is written: the designer's own Excel paints on its own and its windows take the freeze. The second write runs even when the first one raised, so the screen of the instance is off again on every exit.

Returns: String. "OK", the stopped outcome when the instance is gone, or "ERROR (GenerationHost.PaintInstance): ".

Throws:

  • ProjectError.ErrorUnexpectedState When OpenDesignerCopy has not run.

LastAnswer #

last-answer

Read back what the last step of the copy answered

Signature:

Public Function LastAnswer(ByVal stepName As String, Optional ByVal argument As Variant) As String

Asks the step named by LastAnswerStep, which answers "=" for the last step the copy ran, and answers the second part when the first names the step asked about. A step is filed under its own name with its module dropped, and under " " when it took one whole number, so "BuildSteps.BuildSheet" with 2 is read as "BuildSheet 2". While the instance is still at work the question waits, up to thirty minutes. Run calls this after a dropped call; a driver may call it too.

Parameters:

  • stepName: String. The step whose answer is wanted, as Run was given it.
  • argument: Optional Variant. The one argument of that step, when it took one.

Returns: String. What the step answered, or an "ERROR ..." outcome when the answer could not be read back.

Throws:

  • ProjectError.ErrorUnexpectedState When OpenDesignerCopy has not run.
ReleaseInstance

ReleaseInstance #

release

Close the copy, quit the owned instance, delete the copy file

Signature:

Public Function ReleaseInstance() As String

In place nothing is closed and nothing quits: the designer stays where it is. On the instance path the copy is closed without saving and the instance this object started is quit; an instance a Run found gone is left alone, since there is nothing left to quit. The whole body runs under On Error Resume Next, because it runs from the failure exits and from Class_Terminate. A Quit that fails answers the window handle for the driver to log; the answer is kept on ReleaseOutcome too. Calling ReleaseInstance twice is one release.

Returns: String. "OK", or "ERROR (GenerationHost.ReleaseInstance): ..." naming the window handle.
