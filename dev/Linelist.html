Linelist

Facade for the output linelist workbook. Prepare adds every worksheet the linelist needs, prepares the temporary sheets with their hidden names and ListObjects, formats the admin sheet and transfers the VBA code, and SaveLL writes the .xlsb the user receives. AddOutputSheet adds one sheet, SheetExists and SheetNames answer what is there, Wksh, PrintWksh and CRFWksh reach a data entry sheet and its two companions, and Dropdown and Pivots answer the two managers the class builds on first use. LinelistSpecs.Prepare has to have run first: it is what creates the output workbook and points the domain managers at it.

The class uses VB_Creatable = True, so callers build one with Set ll = Linelist.Create(specs) over a New Linelist.

SHEET NAMES AND THEIR SCOPE

A data entry sheet can carry two companions, and each companion is the same name under a prefix: print_ for the printable copy, crf_ for the case report form. ScopedName is the one place that puts a prefix on a name and cuts the result to what Excel accepts, and AddOutputSheet, ResolveWksh and the SheetExists calls all go through it. A sheet created under a shortened name is found again under the same shortened name.

A name the cut actually shortens is filed as a report entry, once per name, so the user learns which sheet came out under a different name.

WHAT THIS CLASS REPORTS

Prepare files its own entries and folds in the ones CodeTransfer filed, so HasCheckings and CheckingValues answer over both. The build driver flushes them into the generation report right after Prepare returns.

A BUILD THAT STOPS KEEPS ITS FILE

DiscardBuild is the one exit of a build that stops before SaveLL. It saves the unfinished workbook as __temp.xlsb in the temporary repository, closes it and answers the path, so the report can name what the user may open. No question is asked: the build may run in an instance nobody sees.

Depends on: LinelistSpecs, LLdictionary, LLSheets, TranslationObject, LLFormat, DropdownLists, CustomPivotTable, TemporaryRepos, Buttons, CodeTransfer, Passwords, HiddenNames, AnaTabIds, ShowHideStore, AnalysisRanges, Checking, BetterArray, LLTranslation, Messenger, LLLog

Lifecycle

Prepare #

prepare

Build the full linelist output workbook from specifications

Signature:

Public Sub Prepare()

Build, save, and error-manage the output workbook.

Runs the whole build of the output workbook:

  1. Takes the temporary repository the specifications created.
  2. Resolves the Geo worksheet once. Every sheet this routine adds goes in before it, and the anchor is passed down as a worksheet.
  3. Writes the two language hidden names and every translated message and sheet name onto the output workbook.
  4. Adds one data-entry worksheet per dictionary sheet name.
  5. Adds the six analysis and custom worksheets.
  6. Adds the six temporary worksheets and prepares them with their hidden names and ListObjects.
  7. Adds the user log worksheet, so the runtime never has to.
  8. Moves the instruction sheet to the front (template workbooks only).
  9. Adds and formats the admin sheet (non-template only).
  10. Transfers the VBA components into the workbook.
  11. Folds the code transfer's report entries into this instance's.

The default worksheet Workbooks.Add made is dropped by LinelistSpecs.Prepare, before any exporter writes to the workbook.

Throws:

  • ProjectError.ErrorUnexpectedState When the specifications have not been prepared.

SaveLL #

save-ll

Save the output workbook as .xlsb with password protection

Signature:

Public Sub SaveLL()

Saves the output workbook in .xlsb format with the configured password, protects the workbook structure via Passwords.Protect, activates the sheet the user should open the file on, closes the workbook and clears the working folder via TemporaryRepos.Remove, which deletes the files and the folder itself. A build that got this far keeps nothing, so nothing of OBTApp_ is left next to the linelist.

Both cached references to the workbook are dropped once it is closed. This instance held one and LinelistSpecs held the other, and a read of either after the close raised an automation error. The read that mattered was the discard reached from a driver's cleanup, so the failure landed inside the error handler and hid the error that got it there.

DiscardBuild #

discard-build

Keep the unfinished output workbook on disk and close it

Signature:

Public Function DiscardBuild() As String

A build that stopped before SaveLL leaves its output workbook open. This saves it as __temp.xlsb in the temporary repository, closes it and drops both cached references to it: the one this instance holds and the one LinelistSpecs holds. The file is marked to survive the drop of the repository, so the user can open what the build managed to write, and the path is answered so the caller can name it in the report.

The repository is the one Prepare took from the specifications. Before Prepare it is built over the output folder entry; with no folder known the workbook is closed with its changes thrown away and the answer is empty. With no output workbook at all the call exits quietly.

A save that fails raises nothing here: this runs from failure paths, and the fault that got the caller here is the one to report. The workbook is closed either way and the answer is then empty.

Returns: String. The full path of the kept file, or empty when nothing was kept.

activate-landing-sheet

Private Sub ActivateLandingSheet(ByVal outWkb As Workbook, _

The generation stops wherever its last step left it, which is the Geo sheet, and a workbook is saved on the sheet that was active. So the sheet chosen here is the sheet the user sees the first time they open the linelist. Choosing it belongs to the build alone: EventLinelist used to choose again on every open, and two places deciding one thing is how the rule drifted apart.

THE INSTRUCTION SHEET, THEN THE FIRST SHEET OF THE SETUP

The instruction sheet is the wanted one and it is not always there. It belongs to template builds, and a specification that turns instructions off carries it very hidden, so a visible one is what counts.

A build without it lands on the first worksheet the SETUP declares -- the first name in the dictionary's sheet list, which is the first data entry sheet the user works in. That is not the same as the first visible worksheet of the workbook: the transfer puts sheets of its own in front of the ones this build adds, and a walk in tab order can answer one of those.

The first visible worksheet closes the list, for a workbook that answers neither. It is a guard rather than a choice -- without it the file would be saved on Geo, which is where the generation stops.

Parameters:

  • outWkb: Workbook. The generated workbook.
  • msgTrads: TranslationObject. The message translations naming the sheets.

PrepareAnalysisLists #

prepare-analysis-lists

Add the choice lists every analysis sheet shares

Signature:

Private Sub PrepareAnalysisLists()

ONE LIST FOR THE WHOLE WORKBOOK

The time units a temporal table can group by are one workbook-level dropdown on the list sheet. Every temporal table binds its own time unit cell to it, and GetAgg in CustomLinelistFunctions reads the same list to turn the chosen label back into a time unit.

Each analysis sheet used to build a copy of its own, which is why there were two spellings of the same five words. A reader that named one of them answered wrongly on the sheet carrying the other, and answered nothing at all in a workbook that carried neither.

The words come from the message translations, so the list is written in the language of the linelist. The dropdown is added once; DropdownLists refuses a second one under the same name and files the reason.

TransferAllCode #

transfer-all-code

Transfer all VBA code components to the output workbook

Signature:

Private Sub TransferAllCode(ByVal transfer As CodeTransfer, _
                            ByVal sheetNames As BetterArray)

Moves the VBA the generated linelist runs on, in five steps:

  1. 36 class modules. ChoiceKeys, ImportMetadata, ImportReport and CheckingOutput joined the list with the import work: LLExporter types ChoiceKeys, LLImporter types the first three, ImportChecking types CheckingOutput and F_ImportRep reads ImportReport, so a linelist without them fails project compilation. LLLog joined with the user log: EventLinelist holds one and the button and form modules write their outcome lines through it. SectionMap, GeoFormCache and AnalysisRanges joined last: EventsLinelistButtons types SectionMap, GeoModule and the F_Geo code-behind call GeoFormCache statically, and GeoModule names AnalysisRanges. None of the three is reached by a bare procedure call, so the call scan reported the set closed while a generated linelist could not compile.
  2. 5 standard modules, carrying the linelist toolbar and its helpers. NO FormLogic MODULE IS TRANSFERRED. Every one of them uses Me and declares control event handlers, which only compile inside a form, and the merged .frm files already carry that code in the code module where it belongs. The two calls into it are written qualified -- F_Export.SetupExportForm and F_ExportMig.HandleAnalysisExport -- so they run the form's copy and need no standard module at all. Transferring the four of them was what cost a delivered linelist its compile.
  3. The ribbon module. A template workbook already carries EventsLinelistRibbon, so its code text is overwritten; otherwise the module is imported.
  4. 10 user forms.
  5. The workbook code module, then EventLinelistSheet into the code module of every hlist2D data-entry worksheet.

Two free scans check the three lists below, and they read different things. scripts/devtools/transferred-code-scan.R reads CALLS: a transferred module invoking a Public procedure defined outside the set. scripts/devtools/linelist-components-scan.R reads NAMES: a type, a predeclared class or an enum the set mentions and does not carry. Run both after any change here.

Parameters:

  • codeTransfer: CodeTransfer. The code transfer engine.
  • sheetNames: BetterArray. The dictionary's unique sheet names, walked once by Prepare and passed down.
